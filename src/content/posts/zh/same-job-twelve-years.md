## 第一周做的不是测试

第一份软件工作，我做的第一样东西不是测试用例，是一个生成测试数据的脚本，因为手写数据比跑测试花的时间还长。第二样是一个小工具，让别人不用来问我也能跑那个脚本。这两样我当时都没当成"我的工作"。我的工作是测试。

十二年后，我的头衔换了四次，现在大部分时间在做给工程团队用的 AI Agent：规划工作、写测试、开 PR。回头看，我从第一周起做的就是同一件事。这一点我看了很久才看出来。

## 四个阶段

**第一阶段：自动化框架。** 摩擦是重复。同样的检查，每次发版手动跑一遍。我做的是一个别人不用懂内部实现就能往里加用例的框架。学到的是：没有第二个人往里提交的框架，只是我自己的脚本换了个长名字。

**第二阶段：内部工具和共享服务。** 摩擦换了位置。跑测试不难了，难的是拿到数据、环境和权限才能跑。我做的是带 API 和界面的服务，当产品来维护，有 roadmap。学到的是：内部工具最难的从来不是代码，是让第二个团队愿意依赖它。

**第三阶段：平台。** 摩擦又换了，跑到系统之间的接缝上：测试管理、工单、CI、被测服务，每个都要单独对接。我做的是一层能跟这些系统全部对接的东西，让人不用一个个去对接；后来是一个 tool server，让 AI 助手也能通过它对接这些系统。学到的是：好的接口比它背后的任何一个系统活得久。

**第四阶段：AI Agent。** 摩擦是速度。开发比周围的人快了。我做的是先把规划、测试、工单做出初稿的 Agent，每一步由人决定。正在学的是：前三个阶段做的东西全都还在用。Agent 能做多少，取决于它能调的工具和拿到的规则，而这正是我前十年一直在做的东西。

## 变的和没变的

| | 第一阶段 | 第二阶段 | 第三阶段 | 第四阶段 |
|---|---|---|---|---|
| 摩擦 | 重复 | 拿不到 | 接缝 | 速度 |
| 做的 | 框架 | 服务 | 一层对接 + tool server | Agent |
| 谁在用 | 我的团队 | 几个团队 | 所有团队，一个接口 | 开着助手的任何人 |
| 算成功的标准 | 有人提交了 | 有人依赖了 | 有人接进来了 | 有人批准了草稿并留下 |
| 没变的 | 摩擦都在人和系统之间 | | | |

最后一行就是这篇要说的。表从左到右读，四列的边界其实很模糊。

## 为什么要写这个

因为头衔两头都误导人。"测试自动化开发"低估了第一年这份工作已经是什么。"AI 赋能"高估了第十二年这份工作有多新。

如果你在类似的路上走得还早，担心地面一直在动：它确实在动，而且不要紧。真正积累下来的不是某个框架、某个服务或某个模型，是看着一群人和一堆系统，能看出哪里在摩擦的能力。
