## Agent 突然不说话了

Agent 跑到一半，突然停了。没有报错，没有提问，也没有总结，这一轮就这么结束了。它最后想做的事情，是用 shell 的 heredoc 写一个小文件。这件事没有任何风险：不 push，不 merge，也不联网。可它就是被拦下了，而且没有任何地方说明原因。

查了一阵才找到原因：拦它的是一个安全 hook，而这个 hook 完全是按写好的逻辑在运行。

## 起因：试试插件好不好移植

我想知道一个 Claude Code 插件到底有多好移植，就把它放到另一个 Agent harness 上跑了一遍。插件基本上都是文本：几个命令、一些 skill、几份 MCP server 配置，再加两个 hook。另一个 harness 读的格式跟它很接近。

大部分工作就是改名。14 个 skill、4 个 MCP server 都搬过去了，完整跑一遍大约一个小时。插件里的相对路径能正常解析，MCP server 的 OAuth 能用，"问用户"这个工具也有对应的版本。中途碰到两个小问题：

- **命令只按文件名命名。** `qa/plan.md` 和顶层的 `plan.md` 都变成了 `/plan`。一共撞了三个名字：`plan`、`status`、`help`。加个前缀，或者单独拆一个插件，都能解决，改动都不大。
- **参数被丢掉了。** 带着工单号调用命令，命令跑起来却拿不到工单号。解决办法是在每个命令里显式写上参数占位符。

这两个问题都很好发现，命令跑错了或者少了工单号，一眼就能看出来。第三个问题就不一样了，它不出声。

## 问题在哪

这个环境里，每条 shell 命令执行前都要过一个安全 hook。它的职责很简单：如果命令要 push 或者 merge，就停下来让人确认。为了做判断，它先用 shell 分词器把命令解析一遍，看实际要执行的是哪个程序、带了哪些参数。

我原以为这种 hook 拿不准的时候会说一声。实际上它没有。分词器解析不了命令时，hook 会退回去在原始文本里搜 "push"、"merge" 这类词。Agent 写的 heredoc 里有一个普通的撇号，就是 "don't" 里那个，分词器处理 heredoc 里的撇号经常出问题，于是解析失败了。退回关键词搜索后，文本里某处匹配上了，hook 就拦了。

接下来，第二个 harness 碰到一个没有可用原因的拦截，处理方式就是直接结束这一轮。从外面看，Agent 就是突然不说话了。

## 其实是两个问题叠在一起

**第一，解析失败后它去猜了。** 在原始文本里搜关键词，跟这个 hook 原本要做的检查根本不是一回事。提到这个词的无害命令会被拦，真正要 push、只是写法绕开了这个词的命令反而能过去。所以退回到关键词匹配并没有让它更安全，只是让结果取决于命令里引号怎么写。

**第二，拦了却不说。** 就算拦得对，没人知道也没用。Agent 没法自己恢复，人也帮不上忙，因为谁都不知道发生了什么。

## 怎么改

我记下的改法不复杂，而且该改的是 hook，不是插件。hook 解析不了命令时，直接拒绝，拒绝的消息里写清楚："读不懂这条命令，所以不执行，请找人确认。"它还是默认拦截，只是现在会有人知道。Agent 把这句话转给人，人看一眼命令，确认没问题，任务接着跑。代价是在少数情况下多问一句，比没声音地停下要好得多。

| | 解析失败就去猜 | 解析失败就明确拒绝 |
|---|---|---|
| 读不懂的命令 | 在原始文本里搜关键词 | 拒绝，原因写明"无法解析" |
| 提到 "merge" 的无害写操作 | 被拦 | 问一句，确认后放行 |
| 写法特殊、藏起来的真 push | 可能漏过去 | 被拒绝 |
| 人看到的 | Agent 突然没声音了 | 一句清楚的话 |
| 时间花在哪 | 翻日志找是哪个 hook 拦的 | 回答一个问题 |

## 为什么是移植时才发现

在原来的 harness 上，这种情况可能很少出现，甚至从没出现过。默认设置不一样，常用的命令不一样，引号的写法习惯也不一样。同一个插件换个地方跑，输入变了，就走到了一条以前没人看过的分支。所以做移植测试，顺便也是在对那些不是你写的部分做一次模糊测试。
