## 背景

我做内部工具很多年了：测试框架、共享服务、那些大家忘了存在直到它坏掉的脚本。做久了会明白一件事：没人用的工具不是免费放着的。它是一笔债，利息不高，但一直在滚。每次它周围有东西变动，就要付一次。

今年一周之内付了两次。

## 搬家时的盘点

我们要把一个测试规划 Agent 从它原来的仓库搬进一个共享插件，别的团队也要安装。Agent 周围已经长出一小片东西：九个命令、一个进度看板、一条把反馈报告生成到仓库里的流程、一套单独试技能的沙箱协议、几个辅助脚本。

默认方案是全部搬。有人问了一句：这些东西最近三十天分别是谁打开过？

答案是：看板，只有做 Agent 的我们三个开过。反馈流程，我们三个。沙箱协议，我们中的一个，用过两次。把工单变成测试方案的那几个命令，每个用户每天都用。help 命令，所有人都在用，而且慢。

## 为什么"留着"不是免费的

"全部搬"背后的假设是：已经做好的东西，留着不花钱。

实际上每一个带过去的界面都要重新做一遍这些事：搬过去，在新环境测，给没见过旧版的人写文档，做安全检查，有人用糊涂了要解释，底下的东西变了要跟着改。没有用户的工具把这些全付一遍，什么都换不回来。而且它让迁移本身的体量翻倍，因为要迁的是所有东西，不只是有人用的那部分。

所以我们把看板、反馈流程、沙箱协议都砍了。插件发出去比原来的仓库还小。之后几周没有一个人问过这些东西去了哪里。

## 留下来的怎么处理

help 命令留下了，后来成了用得最多的一个。它之前慢，是因为要先跑一个脚本检查环境，在某些机器上还会尝试安装东西。我们把它改成只打印一张静态的命令列表，别的什么都不做。改完秒开，一天被打开几十次。整套工具里最有用的，是做得最少的那个。

安装流程也留下了。今年早些时候把一个内部服务接给编码助手的时候，我们学到一件事：推广最容易卡在 README 上。同事用三种客户端，三种配置格式。安装做成一条命令之后，用的人才多起来。这个月插件换 marketplace，切换步骤是四行命令，我发的就是那四行，没有发说明文档。

## 现在做工具之前先问三个问题

这三个问题没有一个是关于工具本身的。

**能不能说出一个具体的人。** 不是"团队"，不是"QA"，不是"开发"。一个具体的人，下个月会为了他本来就在做的某件事打开这个工具。说不出来，那就是在给自己做。给自己做也可以，但要承认，并且计划好什么时候删。

**安装是不是一条命令。** 任何有配置步骤的东西都是一个漏斗，大部分人会在中间放弃。安装不是一行命令，工具就还没发布。

**第一天有没有埋点。** 工具产出的每条记录都带一个"由它产出"的标记，放在没人会改的字段里。这不是为了监控人，是为了以后能回答"最近三十天谁用过"这个问题，不用猜。我之前写过的二月那个聊天面板，这一条没做到：它还在跑，我到现在不知道有没有人在用。这就是一笔我现在背着的债。

## 反过来的例子

同一年，业务方提了一个内部问答机器人的需求。大家的第一反应是 LLM 加检索。实际需求是几十个问题、答案稳定、非工程师能改。我们一天做了一个静态表版本，没用模型，然后故意在旁边又做了一个 LLM 版本，两个并排 demo。静态版答得更快，不编造，负责人自己能改，赢了。这件事的重点不是 LLM 不适合问答，而是能解决问题的最小那个工具，往往才是大家会一直用的那个，而在两个摆在一起之前，谁也不知道是哪个。

## 盘点结果

| 界面 | 三十天内谁用过 | 处理 |
|---|---|---|
| 工单变方案的命令 | 每个用户，每天 | 保留 |
| help 命令 | 所有人，但很慢 | 保留，改成秒开 |
| 进度看板 | 三个开发 | 砍掉 |
| 反馈生成流程 | 三个开发 | 砍掉 |
| 沙箱协议 | 一个开发，两次 | 砍掉 |
| 安装 | 所有人，一次 | 一条命令，搬家时四行 |
| 二月的聊天面板 | 不知道 | 还在跑，下一步先加埋点 |
